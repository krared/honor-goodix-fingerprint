# Goodix 27c6:6f94 на HONOR под CachyOS

Пакет `libfprint-honor` с поддержкой сканера отпечатков Goodix USB `27c6:6f94`.
Патч добавляет USB ID и число этапов регистрации в существующий драйвер
`goodixmoc`. Это адаптация существующего драйвера, а не новый драйвер с нуля.

## Проверено на устройстве

27 октября 2026 года на HONOR `MRB-XXX` под CachyOS:

- libfprint `1.94.100-1.2`, fprintd `1.94.5-2.1`;
- сборка и установка пакета выполнены;
- регистрация завершилась `enroll-completed`;
- проверка завершилась `verify-match`.

Отдельная настройка PAM для sudo применена и проверена по содержимому
установленных профилей. Фактический вызов sudo с отпечатком, вход и
разблокировка ещё не подтверждены. `install.sh` не меняет PAM.
Одинаковый USB ID не гарантирует одинаковый протокол на других моделях.

## Установка

Требуются CachyOS или совместимая система Arch Linux и сканер `27c6:6f94`.
Запускай обычным пользователем; sudo запросит пароль в терминале.

```bash
git clone https://github.com/krared/honor-goodix-fingerprint.git
cd honor-goodix-fingerprint
bash install.sh
fprintd-enroll
fprintd-verify
```

`install.sh` также устанавливает обработчик восстановления после сна,
описанный ниже. Он не меняет PAM и не удаляет сохраненные отпечатки.

При регистрации прикладывай палец по приглашениям программы.
Если отпечатки уже зарегистрированы, после установки сразу запусти
`fprintd-verify`.
Исходники закреплены на коммите релиза libfprint 1.94.100, пакет устанавливается
через pacman. Документация отключена: gtk-doc некорректно обрабатывает
пути с пробелами при упаковке. Повторная сборка перенастраивает Meson.

Для одной только сборки после установки зависимостей:

```bash
makepkg --syncdeps
```

## Как сохранить отпечаток при обновлении CachyOS

10 ноября 2026 года `pacman -Syu` заменил старую локальную сборку
`libfprint 1.94.100-1.2` на `libfprint 1.94.100-2` из Arch. В этой сборке
не было USB ID `27c6:6f94`, и `fprintd` перестал видеть сканер.

Теперь сборка устанавливается под отдельным именем `libfprint-honor`.
Она предоставляет `libfprint` и `libfprint-2.so` для `fprintd`.
При установке pacman предложит заменить прежний `libfprint` в той же
транзакции. Обычный `pacman -Syu` сохраняет установленный `libfprint-honor`.

Если репозиторий уже скачан, один раз перейди на новый пакет:

```bash
git pull --ff-only
bash install.sh
fprintd-verify
```

Пакет собран из закрепленного релиза libfprint 1.94.100. Обновления исходников
libfprint требуют нового проверенного рецепта в этом репозитории и повторного
запуска `bash install.sh`. Если поддержка `27c6:6f94` появится в пакете
дистрибутива, можно вернуться к нему по инструкции отката ниже.

## Если отпечаток перестает работать после сна

3 ноября 2026 года на HONOR MRB-XXX обнаружено зависшее состояние fprintd:
сканер продолжал определяться по USB, оба отпечатка и патч libfprint
сохранились, но журнал содержал:

```text
Device reported an error during identify: Cannot run while suspended.
```

Тот же процесс fprintd пережил сон. USB `power/control` уже был установлен
в `on`, поэтому настройки питания USB не менялись.

Для уже установленного драйвера обнови репозиторий и поставь обработчик
без повторной сборки libfprint:

```bash
git pull --ff-only
sudo bash install-resume-fix.sh
fprintd-verify
```

Установщик создает исполняемый файл
`/usr/lib/systemd/system-sleep/90-honor-fprintd-resume` и перезапускает fprintd.
Если на месте обработчика был другой файл, он сохраняется рядом с суффиксом
`.backup-ДАТА`. Повторная установка того же файла не создает лишнюю копию.

При событии `post`, после пробуждения, обработчик выполняет:

```bash
systemctl --no-block try-restart fprintd.service
```

Это ставит перезапуск активной службы в очередь. Если fprintd не запущен,
он по-прежнему активируется по D-Bus при обращении. Состояние
`inactive (dead)` без обращений само по себе не означает поломку.
Записи отпечатков, параметры PAM и пароль остаются без изменений.

Для разового восстановления без установки обработчика достаточно:

```bash
sudo systemctl restart fprintd.service
fprintd-verify
```

После запроса приложи зарегистрированный палец. Повтори проверку после
обычного цикла сна и пробуждения; успешный результат — `verify-match`.
Не запускай несколько проверок отпечатка одновременно.

Отключить автоматическое восстановление:

```bash
sudo chmod -x /usr/lib/systemd/system-sleep/90-honor-fprintd-resume
```

Снова включить:

```bash
sudo chmod +x /usr/lib/systemd/system-sleep/90-honor-fprintd-resume
```

На ноутбуке подтверждены установка обработчика с правами `root:root 755`
и перезапуск fprintd. Проверка дошла до ожидания пальца и завершилась
по тайм-ауту: успешное распознавание после этой правки и полный цикл
сна/пробуждения пока не подтверждены. Это локальный обход сбоя, а не
исправление кода libfprint.

## Только sudo

После успешных `fprintd-enroll` и `fprintd-verify`:

```bash
sudo bash enable-sudo-fingerprint.sh
```

Если удобнее подтвердить установку в системном окне авторизации:

```bash
pkexec /usr/bin/bash "$PWD/enable-sudo-fingerprint.sh"
```

Скрипт меняет только аутентификацию sudo: создаёт отдельный профиль
`/etc/pam.d/honor-sudo-fingerprint` на основе текущего `system-auth`
и подключает его в `/etc/pam.d/sudo`. Проверка `pam_faillock preauth`
сохраняется перед проверкой отпечатка. После трёх неудачных попыток
или тайм-аута 10 секунд используется обычная проверка пароля.
Polkit, вход в Plasma, SSH и общий `system-auth` не меняются.

Проверка после установки:

```bash
sudo -k
sudo whoami
```

Приложи зарегистрированный палец по приглашению. Скрипт печатает команду
отката с реальным путём к резервной копии:

```bash
sudo bash /etc/honor-sudo-backup.XXXXXX/restore.sh
```

Настройка применена на HONOR MRB-XXX; наличие модуля, подключения профиля
и права установленных файлов проверены. Проверка аутентификации пальцем
в sudo остаётся за пользователем. После обновлений PAM сверяй отдельный
профиль с текущим `system-auth` дистрибутива.

## Sudo, вход в Plasma и KeePassXC вместе

Это альтернативный вариант настройки. Не запускай его поверх варианта
«Только sudo»: сначала выполни откат предыдущей настройки по напечатанной
команде. Аналогично, перед переходом с общей настройки на отдельную
сначала откати общую.

После успешных `fprintd-enroll` и `fprintd-verify` можно отдельно настроить PAM:

```bash
bash enable-desktop-fingerprint.sh --check
sudo bash enable-desktop-fingerprint.sh
```

Скрипт рассчитан на проверенные здесь PAM-профили CachyOS и **Plasma Login**
(`plasmalogin`), а не SDDM. При несовпадении ожидаемых строк он завершится
без изменения профилей. Если настройка уже применена, повторный запуск также
остановится на проверке; для повторной установки сначала выполни откат.

Скрипт добавляет отпечаток для `sudo`, `plasmalogin` и `polkit-1`.
Это касается KeePassXC и остальных запросов Polkit. Сохраняются проверка
`pam_faillock preauth` и пароль после отказа отпечатка либо тайм-аута 10 секунд.
Исходные `system-auth`, `system-login`, профиль блокировки KDE и SSH не меняются.
Стандартный KDE-профиль `kde-fingerprint` в проверенной системе уже содержит
`pam_fprintd`.

Проверка sudo:

```bash
sudo -k
sudo whoami
```

Для KeePassXC 2.8 включи «Быструю разблокировку» в настройках программы,
открой базу мастер-паролем, затем заблокируй её и проверь отпечаток.
Быстрая разблокировка Linux использует Polkit; отдельного PAM-профиля
`keepassxc` не требуется. После полного закрытия программы понадобится
мастер-пароль. Вход по отпечатку сам по себе не разблокирует кошелёк KWallet,
зашифрованный паролем.

Перед изменением файлов скрипт создаёт резервную копию и печатает точную
команду отката вида:

```bash
sudo bash /etc/honor-pam-backup.XXXXXX/restore.sh
```

Используй реальный путь из вывода скрипта. Перед проверкой входа оставь
текущую сессию открытой. Пользовательские PAM-профили содержат копии
системных правил: при обновлениях PAM сверяй их с новыми профилями дистрибутива.

Проверены синтаксис скрипта и режим `--check` на локальных профилях.
Применение настроек и работа sudo, входа и KeePassXC пока не подтверждены.

## Диагностика и откат драйвера

```bash
lsusb -d 27c6:6f94
pacman -Q libfprint-honor fprintd
fprintd-list "$USER"
journalctl -u fprintd -b --no-pager -n 80
```

Чтобы вернуться к пакету из репозитория дистрибутива:

```bash
sudo pacman -S libfprint
sudo systemctl restart fprintd
```

Подтверди замену `libfprint-honor` на `libfprint`, когда pacman спросит.
